4. Latency budgeting  
   | Stage | Typical cost (on Mac M1) |
   |-------|--------------------------|
   | Wake‑word detection | < 5 ms |
   | Audio capture (1 s) | ~ 100 ms (incl. I²S transfer) |

   | LLM generation | 200‑400 ms (depends on model size) |

   - Keep a heartbeat WebSocket ping/pong so the ESP can detect a lost connection and enter a “waiting” LED mode.

4️⃣  Possible pitfalls & mitigations  

| Issue | Symptoms | Mitigation |
|-------|----------|------------|
| Network hiccups on LAN | ESP drops the WebSocket, voice cuts out. | Use a reliable Wi‑Fi network (separate SSID for the device) and implement exponential back‑off reconnection. |
| Whisper‑cpp CPU spikes | Latency spikes > 300 ms when many clips arrive. | Throttle the ESP to send only after a “quiet” period, or use the tiny model (faster but less accurate). |
| Memory pressure on ESP | Crash after a few minutes. | Keep audio buffers ≤ 2 s, free them immediately after ws_send. |

| Licensing | Kokoro is Apache‑2.0, Piper is MIT, Whisper‑cpp is MIT‑licensed, but some models have separate terms. | Verify each model’s LICENSE file before shipping; for a personal project you’re safe, but for a product you’ll need to audit. |
| Audio format mismatches | ESP expects 16‑bit PCM, Mac outputs float32. | Convert once after capture (numpy/scipy pcm_to_float / float_to_pcm). Keep a small conversion helper in the relay daemon. |
